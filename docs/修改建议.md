# MODULO / alu-extrusion-configurator 代码审查与修改建议

> 审查日期：2026-10-18

> 参考提交：`4f8e43131224c401975156c3159617608b54359c`  
> 审查方式：读取 GitHub 仓库源代码的静态审查；**未实际运行构建、单元测试、浏览器或 GPU 验证**。以下所列为从代码可定位的问题及待验证风险，修复效果应由回归测试确认。

## 一、结论与原则

项目已经具备较完善的七产品配置、Three.js 参数化建模、BOM/参考报价、配置分享、GLB 导出、离线单文件构建和基础测试能力。建议暂时减少新功能堆叠，优先完成以下闭环：

**输入配置经过校验 → 几何生成确定 → BOM 统计完整 → 报价语义准确 → GLB/表格/报告输出一致。**

代码审查中的优先级定义：

- **P0（严重）**：存在明确的运行时中断路径，应优先处理。
- **P1（高）**：影响业务正确性、产品输出或非法输入鲁棒性。
- **P2（中）**：输出一致性、覆盖率、性能与可维护性问题。

### CR-01 — WebGL 降级路径的空对象访问（P0）

**代码依据**：

- `src/main.js` 初始化 `hotspots` 时，若 `webglFailed` 则返回 `null`（约第 83 行）。
- `mountActiveProduct()` 仍无条件执行 `hotspots.setHidden(...)`（约第 775 行）。
- 初始化失败时仍调用 `mountActiveProduct()`，目标是降级显示算料（约第 1030–1032 行）。
- `switchTo()` 也在部分位置无条件读取 `anims.exploded`；`anims` 在降级模式下为 `null`（约第 81、886 行）。

**风险**：WebGL 被禁用、上下文创建失败或运行环境不支持时，预期的无 3D 算料模式可能直接抛出 `TypeError`，用户无法正常继续操作。

**建议修改**：

1. 所有 WebGL 专属对象在使用前通过 `?.` 或明确的可用性条件进行保护，例如 `hotspots?.setHidden(...)` 和 `anims?.exploded`。
2. 将“无 WebGL 纯计算模式”视为独立运行路径，逐一审查所有 `scene`、`controls`、`hotspots`、`anims`、`rodHandles` 等对象访问。
3. 在自动化测试中强制让 WebGL 上下文创建失败，切换七种产品，验证算料、报价和导出算料单仍可用。

**验收标准**：WebGL 不可用时，页面无未捕获异常；七种产品可切换、可编辑参数且能获取 BOM；3D 专属操作应正确隐藏或禁用。

### CR-02 — 配置输入验证仍不完整（P1）

**代码依据**：

- `src/config/product.js` 约第 82–103 行的 `normalizeConfig()` 负责补齐 `decks`、`backs`、`bayWidths`，但未强制 `LIMITS.bays`、`LIMITS.levels` 和 `LIMITS.bayWidth` 范围，也未全面处理非法枚举、整数类型和 `NaN`。
- `src/ui/store.js` 的 `set()` 直接调用上述归一化函数。
- `src/ui/persist.js` 对字段做白名单过滤，但**白名单并不等于类型/值验证**，配置可能来自 URL hash 和 localStorage。
- 其他若干产品已经引入 `src/config/clamp.js`，属于已有防线；此问题尤其针对型材架，并建议统一覆盖枚举与跨字段约束。

**风险**：恶意或损坏的分享配置、过大尺寸/层数、非法枚举或非有限数值，可能使循环膨胀、构建器抛错、几何尺寸异常或 BOM 计算失效。

**建议修改**：

1. 建立产品级配置 schema：明确整数、数值上下限、合法枚举、数组长度与元素类型、布尔字段以及字段之间的约束。
2. 所有入口统一校验：hash、localStorage、配置清单恢复及面板更新都应经过 store 层验证。
3. 不合法字段用默认值替换、夹取至边界或返回可见的错误提示；保证校验后值始终可安全进入构建器。
4. 限制 URL 配置有效载荷大小，避免超大配置进入解码/归一化/建模流程。

**验收标准**：测试 `bays=-1`、`levels=1000000`、`bayWidths=[null, "x"]`、未知 `series/decks`、过长数组、非法 Base64/JSON 等场景；应用不崩溃、输出均为有限数值，且配置与预览一致。

### CR-03 — BOM/报价中的板材遗漏和类型错价（P1）

**代码依据**：

- `src/ui/marketPrice.js` 约第 50–52 行直接跳过全部 `c.section === '板'` 的 cutList 条目，假设它们将通过 `stats.panes` 另行计价。
- `src/core/buildWoodCart.js` 将多种胶合板记入 `cutList`，但令 `stats.panes = []`；这些条目因此既不参与定价，也不进入未定价清单。
- `src/ui/marketPrice.js` 约第 72–76 行仅识别 `acrylic`，其他 `panes.kind` 均按 `zincPerM2` 计算。
- `src/core/buildCartTable.js` 将钢化玻璃记录为 `kind: 'glass'`，`src/core/buildBookshelf.js` 使用 `kind: 'board'`；它们都会落入镀锌板单价路径。

**风险**：部分核心板材未被计入总价，未知材料被错价，且页面仍可能显示“全项已计价”。这对参考估价的可信度影响较大。

**建议修改**：

1. 定义统一的 BOM 行结构，例如 `materialKind`、`unit`（`m` / `m2` / `piece`）、`quantity`、`spec`，并由产品生成器输出。
2. 报价规则采用明确的材料类型映射，不再使用“非亚克力 = 镀锌板”的兜底。
3. 缺少对应单价时必须加入 `unpriced`；不可无声地跳过板件。
4. 对所有七种产品设置“BOM 材料数量守恒”断言：每个 BOM 项要么有计价规则，要么被明确标记未计价。
5. 当前项目价格本身是**未核验示例价**，继续保留原有免责声明；修复对象是**漏算/错用计价规则**，不是将示例报价包装为正式采购价格。

**验收标准**：木展车胶合板不会消失在报价之外；玻璃、木板、水磨石/藤编等类型不会静默按镀锌板计价；`complete` 的含义与真实计价覆盖一致。

### CR-04 — GLB 导出包含隐藏几何/LOD 的风险（P1）

**代码依据**：

- `src/ui/modelExport.js` 约第 54–87 行将 `InstancedMesh` 展平为新建 `THREE.Mesh`，并复制世界矩阵，但未继承原网格或祖先节点的可见性条件。
- 创建出的 `THREE.Mesh` 默认可见，即使导出时设置 `onlyVisible: true` 也无法恢复原场景的隐藏状态。
- `src/core/buildGlbFrame.js` 约第 390–392 行创建 `stripsLOD` 并设置 `visible = false`；`src/main.js` 会切换真实板条与 LOD 替身。

**风险**：导出模型可能同时包含真实板条与远景替身，产生重复面、错误零件数量或不必要的模型体积；父节点隐藏时也存在类似问题。

**建议修改**：

1. 明确导出语义：建议 GLB 默认导出完整高精度模型，并有意识地排除纯预览用途的 `stripsLOD`。
2. 展平时沿节点父链判断有效可见性；对有特殊导出策略的网格设置 `userData.exportRole` 或类似元数据。
3. 新增实际的 GLB 二进制导出测试：解析 GLB 并检查 mesh 数量、包围盒、LOD 排除和装配一致性。
4. 保留现有 InstancedMesh 展平策略，避免非通用 glTF 查看器丢零件。

**验收标准**：导出文件中没有隐藏 LOD 备份；在不同相机距离导出的同一配置具有稳定的几何内容。

### CR-05 — 下料统计口径不同（P2）

**代码依据**：

- `src/ui/cutlist.js` 的 `totalCutLen` 对所有 `stats.cutList` 进行 `len * qty` 求和。
- `src/ui/printReport.js` 约第 33 行在合计时明确排除 `c.section === '板'`。
- 对某些产品，`板` 的 `len` 是单边尺寸而非“型材总下料长度”。

**风险**：同一配置在 Excel 和打印报告中出现不同的长度合计；板件单边长度被误当作线材长度。

**建议修改**：

1. 在 `src/core/` 或独立 BOM 模块中实现一个纯函数 `summarizeBom(stats)`。
2. 分别统计线材长度、板材面积、板件数量以及五金数量。
3. 统一 Excel、打印报告、面板统计和参考报价的数据口径；板材建议提供完整长、宽、厚字段。

**验收标准**：相同配置在各输出中主材总长、板材数据、重量和零件数一致。

### CR-06 — 光轴书架导出命名不正确（P2）

**代码依据**：

- `src/ui/modelExport.js` 的 `ROOT_NAMES` 缺少 `books`，默认回退 `AluShelf`。
- `src/ui/cutlist.js` 的 `downloadCutlist()` 没有明确的 `books` 文件名分支，落入铝型材架默认文件名。

**建议修改**：七产品统一配置导出元信息：中文显示名、英文文件名、GLB 根节点名、尺寸字段、报告标题；把已有的零散 if/else 消费端逐步改为查表。

**验收标准**：光轴书架 GLB 和算料单均有独立、正确的名称；其余六种产品命名无回归。

### CR-07 — LOD 判断发生在渲染之后（P2）

**代码依据**：

- `src/main.js` 约第 1107 行调用 `postfx.render()`。
- 约第 1115–1123 行才根据相机距离切换 `strips` 和 `stripsLOD` 可见性。

**建议修改**：将 LOD 状态判定提前到当前帧渲染之前，切换后明确标脏。补充距离阈值来回切换测试，确保不会出现一帧延迟或短暂重叠/空缺。

### CR-08 — `main.js` 过于集中，建议渐进式模块化（P2）

**代码依据**：`src/main.js` 约 1200 行，包含七套 `rebuildXxx`、产品切换、持久化、渲染循环、HUD、导出与 QA 接口。

**建议修改**：不要一次性重写，而是在修复高优先级问题并建立回归测试后，逐步提取：

- `productRegistry`：类型、Store、构建器、面板、元信息注册。
- `sceneLifecycle`：统一重建、旧资源释放、场景挂载、LOD 处理。
- `exportService`：算料单、打印报告、GLB 规则。
- `inputRouting`：产品切换、配置恢复与公共事件。

目标是新产品只需注册，不再在大量 `if/else` 中重复添加逻辑；保留现有几何与用户交互，不以重构为由改变视觉效果。

### CR-09 — 结果级测试不足（P2）

**代码依据**：

- `test/model-export.test.mjs` 约第 40–48 行主要通过源码字符串判断导出实现是否包含关键 API，未验证实际导出的 GLB 内容。
- `test/smoke.spec.mjs` 主要覆盖型材架和光轴展架；部分重建/导出场景会在软件渲染下跳过。

**建议修改**：把关键输出的**结果断言**作为重点，减少仅验证函数或按钮存在的测试。

| 测试 | 需要验证 |
| --- | --- |
| WebGL 失效 | 七产品可切换且可以算料 |
| 异常配置输入 | 不崩溃，数值有限且在允许范围内 |
| 报价覆盖 | 每个实际 BOM 项均已计价或进入未计价列表 |
| GLB 导出 | 隐藏 LOD 不混入，高精度模型包围盒正确 |
| Excel / 打印 | 线材、板材、零件数与重量口径一致 |
| 长时间交互 | 多次切换、重建后无明显 GPU/内存持续增长 |
| 移动设备 | 参数交互、截图、导出时无无响应问题 |

## 三、分阶段实施计划

### 第一阶段：正确性修复（建议优先）

1. 修复 CR-01 的 WebGL 降级空对象访问，补回归用例。
2. 落实 CR-02 的配置层校验，使 URL 与存储配置不可绕过限制。
3. 修复 CR-03 的材质报价映射、漏价与 `unpriced` 语义。
4. 修复 CR-04 的 GLB 可见性与 LOD 导出规则。

**合并条件**：新增用例通过；既有几何/算料基线变化必须附解释；线上非 WebGL 路径不再崩溃。

### 第二阶段：输出一致性与测试

1. 解决 CR-05、CR-06。
2. 抽取 BOM 汇总函数与七产品元信息。
3. 实施 CR-09 的输出级测试，重点覆盖七产品以及 GLB 二进制内容。
4. 每轮保持现有尺寸、装配结构和视觉基线，避免“修报价顺手改几何”。

**合并条件**：同配置的 UI、Excel、打印报告、GLB 数据一致；所有未计价材料清晰展示。

### 第三阶段：性能与维护性

1. 修复 CR-07 的 LOD 更新时序。
2. 基于测试保护渐进式实施 CR-08 的模块拆分。
3. 对高频重建做性能/内存测量，优先使用实际测量定位瓶颈；之后再考虑按需 rAF 唤醒和缓存调整。

**合并条件**：七产品操作体验不退化，视觉截图和核心基线保持稳定，重复配置的重建/导出性能不倒退。

## 四、实施约束与风险提示

- **不要直接覆盖主分支的大批业务逻辑**。建议从 `main` 建立独立修复分支，用小 PR 分批解决，每个 PR 对应问题编号与测试证明。
- **不擅自修改工业结构尺寸或工程假设**。项目算料、承重和报价属于演示/参考数据，所有工程制造相关尺寸仍应以正式节点与工艺确认结果为准。
- **不把示例价格误标为实时报价**。本轮应修复定价覆盖率和类型映射，而非宣称参考价准确。
- **不以静态审查代替运行验证**。报告中的逻辑缺陷已可从代码定位，具体故障复现、性能影响与修复效果仍须在适当浏览器、GPU/软件渲染环境中验证。
- **不要让文档变更混入功能修改提交**。本建议文档独立保存，后续代码修复使用独立 commit/PR。
