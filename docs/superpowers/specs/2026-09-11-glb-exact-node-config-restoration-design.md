# GLB 精确节点配置恢复设计

日期：2026-09-11  
状态：设计已获用户确认，待用户审阅本文档后进入实施计划

## 1. 目标

让“GLB 精确节点”模式保留精确截面和实测拓扑，同时恢复正式配置器应有的参考估价、材料颜色、摆件和背面侧挡板能力，并修正进深构件露出截面的方向。

成功标准：

1. 进深构件露出的精确截面背离背板墙面，朝开放取物/观看侧（用户确认的 B 方向）。
2. 精确模式不再因空算料数据固定显示 ¥0、0.0 kg、0.0 m。
3. 报价采用用户确认的 C 口径：按精确模型可确认构件生成参考算料；没有可靠价格规则的节点或构件明确列为未计价项，不伪造完整报价。
4. 银色、黑色、香槟色可实时作用于精确模式全部铝构件。
5. 摆件开关和背面侧挡板开关在精确模式真实生效。
6. 标准参数架的几何、算料和 177.8 kg / 1956 件 / 104.0 m 回归基线不变。

## 2. 约束与边界

- 遵守仓库 `AGENTS.md`：不修改 `src/core/buildShelf.js`、`src/core/profiles.js`、`src/ui/panel.js`、`src/ui/store.js`、`src/config/product.js`、`src/core/dimensions.js`、`src/core/hotspots.js`。
- 主要实现位于 `src/core/buildGlbFrame.js` 及新增的精确模式独立模块；必要接线只改 `src/main.js`。
- 原 GLB 没有证据支持的隐藏连接方式不新增视觉猜测，也不纳入采购承诺。
- 参考估价不是生产报价；页面继续显示未核验单价与不直接下单的免责声明。
- 精确模式不是生产 CAD、加工图或承重验证。

## 3. 截面方向

当前 `depth` 几何沿 `+Z` 挤出，实例原点放在 `z=-0.20`，构件实际延伸至 `z=+0.17`；原始挤出起始端因此位于墙面侧，与用户要求相反。

实施时保持 GLB 实测 0.37 m 构件长度和原有空间范围不变，并显式记录：

- 墙面/背板侧端点：`z=-0.20`；
- 开放/观看侧端点：`z=+0.17`；
- 用户要求露出的原始精确截面位于开放侧。

具体实现固定为：将 `depth` 几何绕 Y 轴旋转 180°，并把实例锚点改到 `z=+0.17`，使局部挤出起始端朝开放侧、几何仍覆盖 `[-0.20, +0.17]`。布局契约暴露 `backSideZ`、`openSideZ` 与 `exposedSectionZ`，测试直接断言方向，避免只凭相机截图判断。

## 4. 精确模式算料与参考估价

### 4.1 独立统计

精确模式根据 `glbLayout()` 的实际实例生成 `stats`：

- `cutList`：30×30 通高立柱、30×30 分段立柱、30×30 进深梁、20×20 精确层板条、20×10 板下横条；
- `panes`：仅在背面侧挡板启用时加入相应板件/条材统计；若其市场规则不可靠，则保留为未计价项；
- `hardware`：只记录有模型或用户确认依据的项目；隐藏节点连接件使用明确的“精确节点连接方式（未核价）”条目，不猜测型号和单价；
- `partCount`、`profileLengthM`、`weightKg` 从同一份精确实例/算料数据推导，不再写死为零。

### 4.2 未计价策略

现有报价引擎会把没有匹配规则的 `cutList` 或 `hardware` 名称加入 `unpriced`。精确模式利用这一机制：

- 20×20 可匹配现有 2020 参考规则；
- 30×30、20×10 以及未确认节点连接方式若无可靠规则，显示在“有未计价项”中；
- 总价表示“已计价部分小计”，不能暗示完整成交价；
- 精确模式的价格注记改为“参考估价（含未计价项时为已计价小计）”。

若现有公共价格视图无法准确表达“小计”，在不修改受保护 `panel.js` 的前提下，由新增精确模式适配层或 `main.js` 接线层补充状态文案。

## 5. 材质颜色

新增精确模式专用材质工厂，读取 `config.color` 对应的银、黑、香槟色参数：

- 所有铝构件共享选定色系；
- 端盖与挤出侧壁维持轻微粗糙度/明度差异，以保留截面可读性；
- 每个 reveal 分组继续持有独立材质实例，避免渐显动画修改一个分组时影响其他分组；
- `dispose()` 完整释放新增材质。

## 6. 摆件

精确模式新增独立摆件构建器，不调用或修改受保护的 `buildShelf.js`：

- 仅当 `config.props === true` 且对应层存在有效层板时生成；
- 摆件落点由精确模式层板顶面与各跨边界推导；
- 使用确定性伪随机，同一配置保持相同布局；
- 支持书包、书堆、花瓶、收纳盒的现有视觉语义；
- 摆件不计入铝型材采购长度和结构自重，可计入 `partCount` 时必须单独标识为展示件，避免混同结构件。

逐层 `decks` 配置在精确模式至少决定该层是否可放摆件；`none` 层不得生成摆件。亚克力与型材层板的完整精确几何差异不在本次范围内，除非实施检查发现现有 UI 会造成明显错误表达，此时只做最小兼容并在实施计划中列明。

## 7. 背面侧挡板

精确模式新增独立背板/侧挡板组：

- `config.sidePanels === true` 时生成，关闭时完全移除；
- 固定在墙面侧 `z=-0.20` 附近，不遮挡开放侧精确截面；
- 只覆盖存在层板的层，`none` 层不生成；
- 统计与几何使用同一布局数据，避免显示与算料数量不一致。

## 8. 数据流

1. `store` 继续提供标准配置对象。
2. `main.js` 在 `frameMode === 'glb'` 时调用增强后的 `buildGlbFrame(config)`。
3. `buildGlbFrame` 先规范化精确模式所需的 `bayWidths / levels / decks / color / props / sidePanels`。
4. `glbLayout` 生成结构构件、层板落点、背板位置及开放侧端面元数据。
5. 独立构建器分别生成铝构件、摆件、背板和统计。
6. 返回现有正式入口契约：`{ group, groups, layout, stats, bounds, dispose }`。
7. 现有 HUD、尺寸、报价和动画继续消费该契约。

## 9. 测试与验证

按 TDD 逐项先写失败测试：

1. 截面方向测试：精确截面位于开放侧 `z=+0.17`，背板位于负 Z 墙面侧，进深构件包围范围仍为 `[-0.20, +0.17]`。
2. 算料测试：精确模式 `cutList` 非空，材料总长和重量大于零，数量随跨数/层数变化。
3. 未计价测试：30×30/未知节点出现在 `unpriced`，已知 20×20 仍产生已计价小计。
4. 色彩测试：三种 `color` 生成对应材质颜色，分组材质保持隔离。
5. 摆件测试：开关控制 `groups.props`；`none` 层无摆件落点。
6. 背板测试：开关控制背板组，所有背板位于墙面侧。
7. 构建器契约、动画材质隔离和无虚构黑色连接阵列的既有回归继续通过。
8. 完整 `npm test`、`npm run build`。
9. 标准参数架回归确认 177.8 kg / 1956 件 / 104.0 m 不变。
10. 用可见浏览器分别检查银/黑/香槟、摆件开关、背板开关、价格未计价提示以及节点近看方向。

## 10. 非目标

- 不为 30×30、20×10 或隐藏节点杜撰供应商 SKU/成交单价。
- 不把精确模式输出称为正式采购 BOM。
- 不重构标准参数架受保护文件。
- 不改变光轴展架。
- 本设计完成与本地验证不等于授权部署；部署需用户另行明确要求。
