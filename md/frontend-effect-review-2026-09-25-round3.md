## 结论

UI 骨架已经稳定：桌面 1440 六个产品**零碰撞、零越界、零命中失败、零控制台错误**，首帧 1.2–1.5 s。
但效果表达上还有三类问题，按对用户信任的伤害排序：

1. **同一屏幕上出现互相矛盾的数字**：尺寸标注 ≠ 规格卡 ≠ 步进器；大号价格展示的是缺主材的小计。
   这直接损害"参数化实时算料"这一核心卖点。
2. **状态切换时的附属层没有跟随**：爆炸分解后尺寸线、± 热点仍锚在装配态位置。
3. **3D 画面"浮"且偏冷**：无接地、光池网格尺度无意义、远景层板摩尔纹、轮廓光偏蓝。

另外移动端还剩 3 处浮层遮挡（其中「清单」按钮被 tabs 盖住，点不到）。

## 一、P0 · 数字可信度（同屏自相矛盾）

### 1. 尺寸标注与规格卡给出两套"总尺寸"

实测（1440，默认配置，每个产品独立加载页面）：

| 产品 | 3D 尺寸标注 W / H / D | 面板规格卡 W / H / D | 结论 |
| --- | --- | --- | --- |
| 型材架 | 3.42 / 2.79 / 0.40 | 3.42 / 2.79 / 0.40 | 一致 |
| 光轴展架 | 0.92 / 1.38 / 0.42 | 0.92 / 1.38 / 0.42 | 一致 |
| 移动边几 | **0.70** / **0.75** / **0.64** | 0.56 / 0.71 / 0.46 | 宽差 14 cm，深差 18 cm |
| 周转箱架 | **0.76** / **1.13** / **0.64** | 0.68 / 1.15 / 0.58 | 三项全不一致 |
| 木展车 | **0.94** / 2.91 / **0.59** | 0.86 / 2.91 / 0.51 | 宽深各差 8 cm |
| 挂衣架 | **1.44** / **2.52** / **0.54** | 1.43 / 2.50 / 0.53 | 全差 1–2 cm |

挂衣架最典型：同一屏幕上宽度出现 **4 个值**——步进器 1.40、规格卡 1.43、尺寸线 1.44、左下读数 1.40。

**根因**：`main.js:823` 把 `a.bounds` 直接喂给 `dims.update()`；而各 builder 的 `bounds` 是**相机取景包围盒**，
故意加了留白（`buildWoodCart.js:243` `W + 0.14`、`buildCratesRack.js:392` `frameLenX + 0.10 / D + 0.18`、
`buildCartTable.js:318` `+0.16`、`buildHanger.js:381` `+0.04`）。面板规格卡另有一套公式
（`woodCartPanel.js:181` `width + 0.06`、`hangerPanel.js:177` `width + 0.03`）。三处各算各的。

**建议**（不碰原封 `dimensions.js`）：

- 各非原封 builder 在返回值里新增 `envelope: { W, H, D }` = 真实外轮廓（与算料一致），`bounds` 保持取景用途不变；
- `main.js:823` 改为 `dims.update(a.envelope || a.bounds, center)`；
- 各 `*Panel.js` 的 `syncSpecs` 改读 `stats`/`envelope`，删掉面板里手写的 `+0.06 / +0.03` 常数；
- 加一条单测：每个产品 `envelope` 与规格卡显示值相等（这是会被用户看到的真实 bug，值得常驻测试）。

### 2. 大号价格展示的是"缺主材的小计"

| 产品 | 大号价格 | 未计价项（面板小字） |
| --- | --- | --- |
| 木展车 | **¥ 24** | 光轴立柱、顶部挂杆、侧向挂杆、法兰、夹块、角码 |
| 挂衣架 | **¥ 66** | 立柱、主挂衣杆、顶框横杆/纵杆、后框横撑（全部 ⌀30 光轴）… |
| 移动边几 | ¥ 179 | 光轴挂杆、夹块、连接板、螺栓、减震垫、压条 |
| 周转箱架 | ¥ 161 | 周转箱、角件、滑轨垫片 |
| 型材架 | ¥ 3,499 | 有（文案"有未计价项时为已计价小计"） |

一个 72 kg、2.4 m 高的挂衣架标价 ¥66，用户第一眼只会认为"算错了"。30 px 大字是全面板视觉权重最高的元素，
却承载了最不完整的数据；免责信息被放在 11 px 的灰字里。

**建议**（纯表达层，`priceview.js` / CSS 可改）：

- `complete === false` 时切换为"不完整态"：大字降级为 `¥ 66 +`，旁边一枚 warning 色胶囊「另有 5 项待询价」，
  点击展开未计价清单；
- 若主结构件（立柱/横杆）未计价，直接不显示金额，显示「待询价 · 已计 ¥66」；
- 型材架的"参考估价（有未计价项时为已计价小计）"是**条件文案常驻**，应改为按实际状态二选一显示。

### 3. 爆炸分解后，附属层仍锚在装配态

截图 `d1440-hanger-explode.png` / `d1440-profile-explode.png`：

- 尺寸线（2.52 m / 1.44 m / 2.79 m）仍画在装配态外轮廓上，零件已飞离，线框与模型脱节；
- 型材架的 ± 层/跨热点仍然可点，悬浮在飞散的零件中间；在爆炸态加层会重建模型，状态语义混乱；
- chip 的 tooltip「爆炸分解」压在右下尺寸端点上。

**建议**（`main.js` 接线层，`setExplode` 回调里做）：爆炸态 `dimSvg.style.opacity = 0`、
`hotspotLayer.style.display = 'none'`、rod 拖拽手柄隐藏；复位时恢复。代码里已有 `backView` 的同类处理（`main.js:818`），照搬即可。

## 二、P1 · 3D 画面质感

### 4. 模型"浮"在地面上

`scene.js:53` 阴影已按用户要求关闭，地面只剩径向渐变 + 网格光池。结果是所有产品脚部与地面没有任何接触关系，
万向轮、调节脚看起来悬空（木展车、挂衣架最明显）。

用户否决的是"阴影贴图的软阴影观感"，不是"接地感"。可以提一个不同路线请用户确认：

- **烘焙接触遮蔽贴片**：每个脚/轮下放一张 64×64 径向渐变 `MeshBasicMaterial` 小圆片（`depthWrite:false`），
  半径 ≈ 脚径 × 1.5，不透明度 0.25。零 shadow map、零后期，成本是 N 个 instanced quad。
- 这是需要用户拍板的审美决定，不应直接上线。

### 5. 光池网格尺度无意义

`scene.js:120-135`：14 m 平面上 1024px 画 64px 一格 → **每格 0.875 m**。这个数字和任何产品模数（20 mm 型材槽、
0.5 m 跨距、光轴柱距）都没有关系，且在挂衣架/木展车（宽 0.8–1.4 m）下格子比产品还粗，无法充当尺度参照。

建议：改成 0.1 m 细格 + 0.5 m 主格两级（主格略深），网格随相机距离淡出；或直接去掉网格只留光池，
让尺寸标注承担尺度表达。

### 6. 型材层板远景摩尔纹

型材架默认 6×6 全型材层板，iso 视角下密集板条在 1440 截图里出现明显条纹闪烁（`crop-deck.png`），
移动端 780 px 物理宽下更严重（`m390-fullscreen.png`）。原因是亚像素宽的几何细条，MSAA 4× 不足以解决。

建议：层板在相机距离超过阈值时切到"整板 + 条纹法线贴图"的 LOD（带 mipmap 的贴图天然抗混叠）；
近看（节点/槽口视角）才用真几何。如果改 `buildShelf.js` 受原封约束，LOD 切换在 `main.js` 根据相机距离切换
两套 mesh 的 `visible` 即可。

### 7. 整体色温偏冷，银色读成蓝灰塑料

- `scene.js:71` 轮廓光 `0x9fc4ff`（饱和天蓝）强度 0.7，叠加 ACES 后银色型材、挂衣架柜体整体偏蓝灰；
- 挂衣架柜体（`d1440-hanger.png`）大面积平涂蓝灰、无边缘高光，读起来像塑料箱而不是金属钣金/板材。

建议：rim 改为近中性 `0xdfe8f5` / 强度 0.45；柜体类大平面给 0.5–1 mm 倒角（`RoundedBoxGeometry`）以拿到边缘高光，
这是"金属感"最便宜的来源。

### 8. [INFERENCE] 背景幕布被色调映射压灰

`scene.js:37-40` 幕布渐变顶色 `#fbfbfc`，截图实际顶部约为浅灰。three r170 的 `OutputPass` 对整帧（含
`scene.background`）做 ACES，推测这是背景发灰、与面板暖白 `#f5f3ef` 衔接生硬的原因。未逐像素取证；
验证方法：`?nofx` 与默认各截一张比对背景色值。若成立，把背景从 3D 场景移回 CSS（canvas `alpha:true` 已开），
或背景渐变按 ACES 反算预补偿。

## 三、P1 · 移动端遮挡（390×844 触屏，六产品一致复现）

### 9. 「清单」按钮被产品 tabs 盖住，无法点击

实测：`.config-list-btn` 被 flex 挤到品牌区第二行（y 45–72），`#product-tabs` 在 y 42–78、z-index 6 > 品牌层 5。
`elementFromPoint(清单中心)` 命中 tab 按钮，**六个产品全部复现**。第二轮修掉的桌面问题，在移动端以另一种形式回来了。

根因：移动端 `.brand-overlay`（`styles.css:1082`）只加了 `display:flex; justify-content:space-between; align-items:center`，
没有覆盖基础规则 `styles.css:94` 的 `flex-direction: column`。于是 space-between 作用在纵轴、`align-items:center`
把品牌与清单**上下堆叠并水平居中**（brand x 146–244，清单 x 162–228），清单落进 tabs 行。
修法：移动端补一行 `flex-direction: row`，清单按钮即回到右上角；再按 §三-10 统一右侧按钮组。

### 10. 「全屏看模型」按钮压住 MODULO 字标

`.btn-mobile-fullscreen` 绝对定位 `right: 94px`（`styles.css:1191`），与居中的品牌字标重叠 42×27 px；
全屏态按钮变黑底后更明显，字标只剩「MODU」（`m390-fullscreen.png`）。
修法：全屏按钮与清单按钮放进同一个右对齐 flex 容器，由布局而非魔数定位。

### 11. 沉浸全屏态仍保留 tabs 与品牌

全屏看模型的目的是沉浸，但顶部 tabs 条（36 px）+ 品牌行仍在。建议全屏态只保留「返回编辑」与底部 chip 条。

### 12. 触控目标偏小

移动端 chip 28×28、tabs 高 28、清单 66×27、全屏按钮 95×27，均低于 44 pt（Apple HIG）/ 48 dp（Material）。
建议 chip 升到 36×36，视觉尺寸不变时用 `::before` 扩热区。

### 13. 1100 宽度读数与 chip 条重叠

型材架 1100×760：`hudLeft × hudRight` 重叠 10×46 px。读数第三行免责文案较长。
建议 901–1280 档位给 `#hud-left` 加 `max-width: calc(50% - 200px)` 并省略。
